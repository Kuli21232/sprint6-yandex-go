Как отправлять проект на ревью
Кликните на вкладку «Ревью». Там вы увидите форму для отправки ссылки.
image
Вставьте ссылку на ваш последний актуальный Pull Request (PR).
image
Чтобы отправить работу на проверку, нажмите "Отправить". Ревьюер назначится автоматически.
image
Для вашего удобства примерно через час начнёт отображаться время отправки.
image
Когда ревьюер приступит к проверке, это также отобразится в интерфейсе формы.
image
Если у ревьюера будут замечания по коду, он оставит комментарии и отправит код на доработку.
image
После того как вы исправите код с учётом комментариев ревьюера, не забудьте закоммитить изменения. Новый коммит появится в Pull Request, и вы сможете отправить работу на повторную проверку.
Внимание!

Для повторного ревью нужно снова отправить ссылку на PR через эту форму. Только так ревьюер узнает, что вы закоммитили изменения. Иначе он не увидит вашу работу в списке ожидающих проверки.
Если комментариев у ментора больше нет, работа будет засчитана, а значит, спринт пройден. Это отобразится в интерфейсе Практикума.

Как работать с итоговыми проектами на GitHub?
Все финальные задания тем хранятся на GitHub, и чтобы их выполнять, вам понадобится аккаунт GitHub. Для каждого задания предоставляется ссылка, которая будет вести на репозиторий в Yandex-Practicum с прекодом. Ниже пошагово рассказывается, как с ней работать.
Что нужно сделать?
Шаг 1
Перейдите по ссылке, которая указана в задании. Вы окажетесь на странице GitHub с прекодом.
Шаг 2
Внимание!

Чтобы задание было принято ревьювером, нужно обязательно создать новый репозиторий на своем аккаунте, нажав на кнопку Use this template. Если вы создадите запрос на изменение (Pull Request) в репозитории Yandex-Practicum, то работа принята не будет.

Чтобы работать с проектом, нужно нажать на кнопку Use this template и в выпадающем списке выбрать Create a new repository.

Вы окажетесь на странице создания нового репозитория Create a new repository. В поле Repository name * задайте имя нового репозитория, который будет создан на вашем аккаунте, а затем нажмите на кнопку Create repository.
3
Проект появится в вашем аккаунте. Это видно в левом верхнем углу: под названием репозитория написано, откуда был сгенерирован репозиторий.

Шаг 3
Проект продублирован в вашем аккаунте, это ваша стартовая точка. Но работать с проектом и вносить изменения вы будете на своем компьютере. Поэтому сейчас вам надо из аккаунта клонировать проект на свой локальный компьютер. Чтобы получить ссылку на репозиторий, нажмите кнопку <> Code.
Появится окно с ссылкой и кнопка для её копирования. Скопируйте ссылку в буфер обмена.

Теперь на локальном компьютере зайдите в директорию, где будут ваши проекты, и в терминале (консоли) выполните команду:

git clone <тут вставьте ссылку из буфера обмена> 
и нажмите Enter.
Так будет создана директория по имени репозитория, и вы можете в неё войти.
Шаг 4
Следующим шагом вам нужно создать ветку, в которой вы и будете вносить изменения. Выполните команду в директории проекта:

git checkout -b <имя ветки, например first-iteration> 
Вы сразу переключитесь на новую ветку и теперь можете выполнять задание, править код и запускать программу.
Шаг 5
Перед отправкой выполненного задания на ревью, вам нужно перенести проект обратно на GitHub и протестировать его встроенными автотестами.
Все изменения, которые вы внесли, отправьте на GitHub с помощью этих команд. Они добавляют изменения, утверждают их и отправляют на GitHub:

git add .
git commit -m "<здесь имя вашего коммита, например first commit>"
git push --set-upstream origin <имя ветки которую вы дали выше> 
Шаг 6
Теперь зайдите в свой репозиторий проекта на GitHub. Должна появиться новая надпись, где указывается имя ветки и когда она была загружена: например first-iteration had recent pushes less than a minute ago. И рядом — кнопка Compare & pull request.

Нажмите эту кнопку, чтобы создать новый Pull Request. Pull Request (сокращенно PR, пиар) — это ветка с вашими изменениями кода и запрос на эти изменения.
В поле Add a title напишите название вашего PR, например Первая итерация и нажмите кнопку Create pull request.

Шаг 7
Чтобы поделиться заданием, перейдите на вкладку Pull requests, выберите свой PR, скопируйте URL из браузера и отправьте его ревьюверу.
На этом всё. Помните: ошибки и доработки — это нормально! Совершая ошибки, вы учитесь, а исправляя их, становитесь лучше. Мы всегда готовы помочь. Успехов!
Внимание!

Если для задания предусмотрены автотесты, они запустятся автоматически после отправки изменений на GitHub(push). Посмотреть статус можно во вкладке Actions. Перед отправкой вашего PR ревьюверу на проверку, убедитесь, что все тесты пройдены, иначе работу вернут.

Финальное задание
Наверное, каждый хоть раз загружал файлы в какой-либо сервис. Это могли быть фотографии или клипы, которые вы добавляли на свой аккаунт в социальной сети, или мем, которым вы делились со своим другом. Выполнив это задание, вы будете иметь представление, как это работает «под капотом» в Go.
Вам предстоит написать конвертер азбуки Морзе. Выполнив этот проект, вы научитесь:
Создавать HTTP-сервер.
Парсить форму HTML.
Создавать и регистрировать хендлеры в маршрутизаторе.
Подгружать файлы из HTML-формы.
Автоматически определять содержимое файла (текст или код Морзе).
Использовать методы из пакета, который мы для вас написали, чтобы конвертировать текст в код Морзе или наоборот.
Как и в заданиях предыдущих спринтов, у вас будет шаблон проекта, который вы будете развивать. Вот ссылка на него.
Ваш проект будет состоять из трёх пакетов, не считая основного: 
Пакет server. Здесь вы реализуете функцию, которая создаёт новый сервер, http-роутер и зарегистрирует ваши хендлеры в нём.
Пакет service. В этом пакете вам нужно будет реализовать функцию, которая будет автоматически определять, в каком виде (текст или код Морзе) вы получили данные из файла.
Пакет handlers. В пакете handlers вы создадите два хендлера:
первый для отправки файла с формой HTML index.html;
второй для загрузки файла с данными из этой формы.
Файл index.html находится в корне проекта.
Два тестовых файла test и test12 тоже находятся в корне проекта: в первом файле код Морзе, во втором — простой текст. Когда ваше приложение будет готово, и ваш сервис будет запущен, вы можете подгружать эти файлы через форму, чтобы проверить, что сервис работает.
В проекте также есть папка pkg, в которой находится пакет morse. Этот пакет мы написали, чтобы вы могли его использовать для конвертации кода Морзе в текст и обратно. Для этого вам понадобятся всего две функции:
Функция ToText(morse string) string, которая принимает и возвращает строку. Эта функция конвертирует код Морзе в текст.
Функция ToMorse(text string) string, которая так же принимает и возвращает строку и конвертирует текст в код Морзе.
Функции работают с русским алфавитом. Так сделано намеренно, чтобы было нагляднее.
Для создания http-роутера используйте стандартную библиотеку.
Ну что ж, довольно прелюдий, начинаем!
Техническое задание
Пакет service
В этом пакете вы реализуете функцию автоматического определения кода Морзе или обычного текста из переданной строки. Если передан обычный текст, функция должна переконвертировать его в код Морзе и вернуть; и наоборот — если был передан код Морзе, функция должна переконвертировать его в обычный текст и вернуть. 
Для реализации этой функции придётся обратиться к стандартной библиотеке, а именно — к пакету strings. В этом пакете есть хорошие примеры, которые демонстрируют, как можно решить эту задачу. 
Не забудьте обработать ошибки и вернуть их.
Пакет handlers
В этом пакете вы реализуете два хендлера. 
Для корневого эндпоинта / нужно реализовать хендлер, который возвращает HTML из файла index.html.
Второй хендлер для эндпоинта /upload должен выполнять следующие действия:
Парсить html-форму из файла index.html.
Получить файл из формы (не забудьте его закрыть).
Прочитать данные из файла.
Передать эти данные в функцию автоопределения из пакета service, которую вы создали, чтобы получить переконвертируемую строку.
Создать локальный файл. Эта операция обычно небезопасна и так делать не рекомендуется, но в рамках нашего задания хотелось бы более наглядного результата, поэтому мы решились на этот шаг, ради видимого результата. А вообще, обычно используют временные файлы.
Записать в локальный файл результат конвертации строки. Для генерации имени файла вы можете использовать время с помощью time.Now().UTC().String(). Чтобы получить расширения файла, используйте filepath.Ext().
Вернуть результат конвертации строки.
Там, где это необходимо, обработайте возможные ошибки. Статус при возникновении ошибок http.StatusInternalServerError.
Пакет server
В этом пакете вы реализуете функцию для создания http-сервера. 
Алгоритм реализации:
Создайте структуру сервера с полями для логгера (log.Logger) и http-сервера (http.Server).
Создайте функцию, в которой нужно создать http-роутер. Функция принимает log.Logger и возвращает экземпляр структуры вашего сервера.
Зарегистрируйте ваши хендлеры в http-роутере.
Создайте экземпляр структуры http.Server. Для настройки вашего сервера используйте следующие поля:
Addr — используйте порт 8080.
Handler — передайте ваш http-роутер.
ErrorLog — передайте ваш логгер.
ReadTimeout — таймаут для чтения. 5 секунд.
WriteTimeout — таймаут для записи. 10 секунд.
IdleTimeout — таймаут ожидания следующего запроса. 15 секунд.
Верните ссылку на ваш сервер.
Основной пакет
Здесь, в функции main() нужно создать логгер, далее создать сервер с помощью вашей функции из пакета server, и запустить его. Если при запуске сервера возникают ошибки, выведите их с помощью логгера на уровне Fatal.
